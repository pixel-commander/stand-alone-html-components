MARKING THIS PROJECT
====================

Two files leave here: stamp.html and settings.js. They are written at the
end, together, by hand. Nothing checks them. Everything downstream believes
them.


THE MARKUP IS ALREADY WRITTEN
index.html is the truth. stamp.html is that same markup with markers added
and nothing else changed. Not tidied, not renamed, not restructured. If the
two drift, the one that was previewed is the one that was right.


A MARKER SAYS REPEAT OR FILL
Repeat marks the one node that stands for many. Write the row once. Never
three times, never a copy per value in the demo.

Fill marks a node whose text or attribute comes from a prop. Everything
unmarked is literal and carries over as it stands.


EVERY MARKER NAMES A PROP THAT EXISTS
A marker pointing at a prop settings.js does not declare is a broken file.
A prop declared and never marked is a lie about the markup. Read both, in
full, side by side, before either is finished.


DECLARE THE SHAPE, NOT THE EXAMPLE
data: [{ id: '', value: 0 }] states what a row is. The demo values stay in
script.js where they belong. A shape with one real row in it is a shape that
will be shipped as data.


DEFAULTS ARE THE FALLBACK THAT WAS ALREADY THERE
Whatever the built thing did when a value was missing is what the default
says. It is read off the working project, not decided fresh.


NAMES CARRY OVER UNCHANGED
Every class, every prop, every key keeps the name it already has. A name
that does not exist yet is a question, never a guess, and the work stops
until it is answered.


WHAT CANNOT BE CARRIED IS SAID OUT LOUD
An asset path relative to this folder is relative to nothing once the
component leaves. A style that only worked because of the page around it
goes with it. Neither is quietly rewritten and neither is dropped — both are
named, in the open, before this is called done.


DONE MEANS THE DEMO STILL DRAWS
The demo is the fixture. If the marked markup and the declared props cannot
produce what the page produced, the marking is wrong, not the page.
